# keychain-secrets

비밀 값은 로그인 키체인의 일반 암호 항목에만 저장한다. 셸 설정 · 파일에 값을 적지 않고, 환경 변수는 셸 시작 때 키체인에서 읽어 만든다.
스크립트는 이 스킬 폴더(스킬을 불러올 때 표시되는 Base directory)의 `scripts/` 에 있다 (아래 `$D`). 플러그인으로 설치하면 버전마다 경로가 달라지므로 고정 경로를 쓰지 않는다.

## 항목 구성
암호 앱의 새 암호 창과 같은 칸을 키체인 항목에 담는다.

| 칸 | 키체인 속성 | 규칙 |
|---|---|---|
| 제목 | 서비스 이름 · 레이블 | `env/<NAME>`. `NAME` 은 영문 대문자 · 숫자 · `_`, 서비스 단위 (예: `env/JIRA`). 이름 하나에 항목 하나 |
| 사용자 이름 | 계정 | 함께 쓰는 로그인 ID. 없으면 `$USER` |
| 암호 | 암호 | 토큰 · 비밀번호 |
| 웹사이트 | 일반 속성(`-G`) | 값을 보낼 곳. 이 호스트로만 보낸다 |
| 메모 | 설명(`-j`) | 이 항목을 쓰는 방법 · 제약. 쓰기 전에 읽고 따른다(아래 메모 절). 비밀은 넣지 않는다 |

`env/` 로 시작하는 항목은 등록 없이 모두 환경 변수가 된다. 서비스마다 따로 설정하지 않는다.
- `<NAME>_USER` = 사용자 이름, `<NAME>_PW` = 암호, `<NAME>_URL` = 웹사이트, `<NAME>_MEMO` = 메모 (웹사이트 · 메모는 있을 때만)
- 예: `env/JIRA` → `JIRA_USER` · `JIRA_PW`, `env/DEV_MEMBER_DB` → `DEV_MEMBER_DB_USER` · `DEV_MEMBER_DB_PW` · `DEV_MEMBER_DB_URL`
- `~/.zshrc` 에 넣은 로드 줄(README 의 "환경 변수 자동 등록")이 셸 시작 때 `scripts/load-env.zsh` 로 export 한다(약 0.1초)

값(암호)은 출력 · 파일 저장 · 로그 · 대화에 남기지 않는다. 확인이 필요하면 길이나 종료 코드만 본다.

## 목록
이름 · 사용자 이름 · 웹사이트 · 메모를 보여 준다. 암호는 읽지 않는다.
```bash
python3 $D/kc.py list
```

## 메모
메모는 그 항목을 어떻게 써야 하는지 적는 칸이다. 저장할 때 채우고, 쓸 때 읽는다.

**쓸 때**
- 작업에 쓸 항목을 고를 때 목록의 이름 · 웹사이트 · 메모를 보고 고른다. 후보가 여럿이면 메모로 가르고, 그래도 모호하면 묻는다
- 쓰기 전에 그 항목의 메모(`$<NAME>_MEMO`, 없으면 `python3 $D/kc.py get NAME memo`)를 읽고 따른다
  - 인증 방식(Basic · Bearer · 헤더 이름 등), 대상 환경(dev · qa · prod), 허용 작업(읽기 전용 · 조회만 등), 만료일
- 메모의 제약과 요청이 어긋나면 실행하지 않고 그 내용을 알린다 (예: 메모 "읽기 전용" 인데 UPDATE 요청, 만료일 지남)
- 메모에 적힌 제약을 이유로 멈췄으면 그 문장을 인용해 보고한다

**저장할 때**
- 요청 · 대화에서 알 수 있는 내용으로 메모 제안값을 만든다. 형식: `<용도>. 인증: <방식>. 범위: <권한>. 주의: <제약>. 만료: <YYYY-MM-DD>`
  - 예: `Jira Cloud API. 인증: Basic, 사용자 이름은 Atlassian 이메일. 범위: 이슈 읽기/쓰기. 만료: 2027-11-26`
  - 예: `회원 DB dev (MySQL). 인증: 사용자/암호. 주의: 읽기 전용, SELECT 만`
- 모르는 항목은 빼고, 추측한 값은 넣지 않는다

## 저장
- 비밀 값은 대화로 받지 않는다. 사용자가 값을 붙여 넣으려 하면 막는다
- 입력창(제목 · 사용자 이름 · 암호 · 웹사이트 · 메모)을 띄워 받는다. 요청에서 알 수 있는 제목 · 사용자 이름 · 웹사이트 · 메모를 제안값으로 넣고,
  모르면 빈 문자열로 둔다. 같은 이름이 있으면 빈 제안값을 기존 값으로 채운다. 사용자가 창에서 고칠 수 있다.
  사용자가 입력할 때까지 기다리므로 timeout 을 넉넉히(300000) 준다
  ```bash
  $D/save.sh env/JIRA user@example.com https://example.atlassian.net "Jira Cloud API. 인증: Basic. 범위: ..."
  ```
- 출력은 저장한 칸 값과 암호 길이. 사용자 이름을 바꿔 저장하면 예전 항목은 지운다
- `"` · `\` 가 들어간 칸, 빈 사용자 이름 · 암호는 저장하지 않는다
- 입력창을 쓸 수 없을 때(SSH 등)는 터미널에서 직접 실행할 명령을 준다. `-w` 를 마지막에 두면 값을 보이지 않게 두 번 입력받는다
  ```bash
  security add-generic-password -U -a <사용자 이름> -s env/NAME -l env/NAME -G <웹사이트> -j "<메모>" -w
  ```
- 암호 앱 · 키체인 접근 앱의 새 항목 창은 명령으로 값을 채워 열 수 없다. 사용자가 앱을 원하면 `open -a "Keychain Access"` 로 열고
  위 표대로 넣게 안내한다. 앱에서 만든 항목은 처음 읽을 때 허용 창이 한 번 뜨며 "항상 허용"을 누르게 한다

## 사용
- 값은 그 항목의 웹사이트(`<NAME>_URL`) 호스트로만 보낸다. 웹사이트가 비어 있으면 메모 · 요청에서 용도가 분명할 때만 쓴다
- 변수를 echo · 출력하지 않는다. 명령 안에서 참조만 한다
- 셸에 변수가 있으면(`[ -n "$JIRA_PW" ]`) 바로 쓴다
  ```bash
  curl -s -u "$JIRA_USER:$JIRA_PW" "$JIRA_URL/rest/api/3/myself"
  ```
- 없으면(load-env 적용 전에 시작한 세션 · 방금 추가한 항목) `with-env.sh` 로 명령 하나에만 넣는다.
  바깥 셸이 먼저 풀지 않게 `sh -c '...'` 를 작은따옴표로 감싼다
  ```bash
  $D/with-env.sh sh -c 'curl -s -u "$JIRA_USER:$JIRA_PW" "$JIRA_URL/rest/api/3/myself"'
  ```
- 항목이 없으면 변수가 비어 있다. 목록으로 확인하고 저장 방법을 안내한 뒤 멈춘다

## 이름 변경
나머지 칸은 그대로 두고 이름만 바꾼다. 새 이름이 있으면 멈추고, 새 항목 저장을 확인한 뒤에만 기존 항목을 지운다.
사용자가 새 이름을 정하지 않았으면 대화로 묻는다. 끝나면 그 이름을 쓰던 곳(메모리 · 다른 스킬의 명령)도 고친다.
```bash
$D/rename.sh JIRA JIRA_CLOUD
```
다른 칸(사용자 이름 · 웹사이트 · 메모)을 고칠 때는 저장 입력창을 같은 제목으로 띄운다.

## 삭제
삭제할 항목의 목록 줄을 보여 주고 확인을 받은 뒤 실행한다.
```bash
security delete-generic-password -s env/NAME
```
